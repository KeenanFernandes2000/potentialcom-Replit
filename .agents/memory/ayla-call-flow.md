---
name: Protect Ayla call flow
description: Constraint for any future edits to the Ayla page and its conversion experience.
---

Do not rebuild, simplify, replace, or otherwise alter the Ayla form, its fields, submission behavior, backend integration, or the immediate AI voice-call startup after a successful submission, unless Mamoon asks. Surrounding page copy and presentation may be refined without touching that flow.

**The flow (since 14 Nov 2026, Mamoon's decision):** a short form (first and last name, work email, organisation, role; phone with its country code and website optional), then the call starts at once. Two engines (`client/src/lib/aylaVoice/engine.ts`). **The single switch is Ayla's server:** the page uses the brain whenever agents.potential.com's `GET /api/ayla/voice/status` (sent with the page's Origin) answers `{available:true}`, and Vapi otherwise (`available:false`, an error, a non-200, or no answer within 2.5 s). Turning `AYLA_VOICE_MODE` off on Ayla's server is therefore the instant rollback to Vapi for every visitor, with no republish of this site. Testers: `?ayla_voice=vapi` forces Vapi (the server is not asked); `?ayla_voice=brain` asks for the brain but still needs the server to say available. The page asks once per visit, when the visitor first focuses the form, and waits for that answer on submit, so a page view alone sends nothing to Ayla's server. There is no build-time engine flag: `VITE_AYLA_VOICE_ENGINE` was removed (14 Nov) because Replit did not pass the Secret into the Vite build and the published bundle compiled it to a constant "vapi"; setting it now does nothing.
- **Brain (Ayla's own server, agents.potential.com):** the form goes to `POST /api/ayla/voice/intake`, which saves the CRM contact (channel Voice) before the call. The site keeps its own `ayla_consultations` row and team email through `/api/ayla/voice-consultation`, which never reaches the CRM intake (one CRM contact, not two). The honeypot is checked on the site. The call is WebRTC, audio only (`AylaVoiceModal.tsx`), with the microphone granted before the call is created; panels (code, booking, demos) and captions come from the server's event stream.
- **Vapi (the rollback, kept for the first week):** the form posts to `/api/ayla/consultation` (CRM intake, campaign `website-ayla`), then `AylaCallModal.tsx`. The brain path falls back to this when Ayla's server is unavailable or unreachable.

**Server settings for the brain path (Replit Secrets; the build-time one is `VITE_AYLA_VOICE_API`, default `https://agents.potential.com`, and like any `VITE_` value it only takes effect if the build actually receives it):**
- `AYLA_SITE_IP_LIMIT` = `off` | `observe` | `enforce` (default `observe`; anything else is `observe`). The per-IP limit (3 per hour) on `/api/ayla/voice-consultation`. `observe` never refuses and logs `[ayla-voice] ip-limit observe: would have refused ...` each time it would have; `enforce` refuses with 429; `off` skips it. The global (15 per 10 min) and per-email (3 per 10 min) limits refuse in every mode. The mode is logged at start as `[ayla-voice] ip-limit mode: <mode>`. Do not set `enforce` until the ip-chain line shows `TRUST_PROXY_HOPS` is right: otherwise every visitor can share the load balancer's address and the limit becomes 3 per hour for the whole site.
- `TRUST_PROXY_HOPS` = a whole number, unset by default. How many X-Forwarded-For hops (counted from the right, the socket address being hop 0) belong to the platform. Unset, `server/client-ip.ts` skips private, loopback and link-local hops and takes the first public one, which is wrong if Replit's public load balancer adds itself to the chain. If it is larger than the chain that arrived, the address is "unknown" and that request is not limited per IP. IPv6 visitors are counted per /56, as Ayla's server does.
- `[ayla-voice] ip-chain ...` (logged on the first form after each start, then at most hourly; no addresses): `xff_entries`, each entry's kind right to left, the socket's kind (`remote=`), and `rightmost_public_distinct=D of last N requests`. If D stays 1 across many visitors, that rightmost public entry is the load balancer: set `TRUST_PROXY_HOPS` to skip it (e.g. `right_to_left=public,public remote=private` with D=1 means `TRUST_PROXY_HOPS=2`), redeploy, and check the would-have-refused lines are rare before switching to `enforce`.

**Why:** The immediate voice conversation is an intentional and required part of the conversion experience, not a standard lead form that can be safely replaced.

**How to apply:** For Ayla page work, isolate and preserve the complete form-to-call path. Do not add a second form, booking widget, qualification score, or competing conversion flow. Call and submission logic belongs in `client/src/lib/aylaVoice/` with bun tests (`bun test client/src/lib/aylaVoice`).

### Reading `distinct_by_position` (added 14 Nov)
The ip-chain line now ends with `distinct_by_position=a,b,c,…`: for each X-Forwarded-For position counted from the right, how many different values the last 50 forms had (addresses are never logged). It also logs at the 5th, 20th and 50th form, not only hourly. The platform's own hops show 1 (or a small number); the visitor's position shows roughly one value per visitor. First Replit sample (14 Nov): 4 public entries behind a loopback proxy, so the rightmost entry is not the visitor. Set `TRUST_PROXY_HOPS` to the number of positions to the right of the visitor's (with the loopback socket counted as one hop, so hops = position index + 1 when positions are counted from 0 at the right), then switch `AYLA_SITE_IP_LIMIT` to `enforce`.
